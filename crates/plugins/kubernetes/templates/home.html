Connecting a cluster

DOC reads a cluster as a service account that can list namespaces, nodes, pods, deployments and replica sets, and nothing more: the Settings page refuses one that could change anything or read secrets. Apply this to the cluster:

{{ manifest }}

Then make a kubeconfig from its token, with kubectl pointed at the same cluster:

SERVER=$(kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}')
CA=$(kubectl -n doc-system get secret doc-reader-token -o jsonpath='{.data.ca\.crt}')
TOKEN=$(kubectl -n doc-system get secret doc-reader-token -o jsonpath='{.data.token}' | base64 -d)
cat <<EOF
apiVersion: v1
kind: Config
clusters: [{name: cluster, cluster: {server: "$SERVER", certificate-authority-data: "$CA"}}]
users: [{name: doc-reader, user: {token: "$TOKEN"}}]
contexts: [{name: doc, context: {cluster: cluster, user: doc-reader}}]
current-context: doc
EOF

Add what it prints under Clusters on {% if admin %}the Settings page{% else %}this plugin's Settings page{% endif %}, named as you like, such as prod-eu, and give it an environment under Environments. The server must be reachable from wherever this plugin runs.
