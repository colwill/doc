When you run one, Agent Smith uses your access, and you are its requester. Against production it only reads, and lists what is left for you to do.

Connect your agent

Claude Code, Claude Desktop, GitHub Copilot in VS Code, the Copilot coding agent and any other MCP client can use DOC through one server. It acts as you, with your access and nothing more, so make a personal access token for it. A scoped token reaches only Agent Smith's own tools.

Server
{{ url }}
Transport
Streamable HTTP, with your token as a bearer token

Claude Code

claude mcp add --transport http doc {{ url }} \
  --header "Authorization: Bearer $DOC_TOKEN"

GitHub Copilot in VS Code

In .vscode/mcp.json; VS Code asks for the token once and keeps it.

{
  "inputs": [{ "id": "doc-token", "type": "promptString", "description": "DOC personal access token", "password": true }],
  "servers": {
    "doc": {
      "type": "http",
      "url": "{{ url }}",
      "headers": { "Authorization": "Bearer ${input:doc-token}" }
    }
  }
}

The Copilot coding agent

In the repository's settings, under Copilot's MCP configuration, with the token as the secret COPILOT_MCP_DOC_TOKEN in its Copilot environment.

{
  "mcpServers": {
    "doc": {
      "type": "http",
      "url": "{{ url }}",
      "headers": { "Authorization": "Bearer $COPILOT_MCP_DOC_TOKEN" },
      "tools": ["*"]
    }
  }
}

Claude Desktop

Add it under Settings, Connectors, as a custom connector with this address, or in claude_desktop_config.json through mcp-remote:

{
  "mcpServers": {
    "doc": {
      "command": "npx",
      "args": ["mcp-remote", "{{ url }}", "--header", "Authorization: Bearer ${DOC_TOKEN}"],
      "env": { "DOC_TOKEN": "your personal access token" }
    }
  }
}
