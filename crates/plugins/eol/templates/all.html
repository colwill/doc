Reading it from your own tools

DOC serves its copy in endoflife.date's own format, so a script, pipeline or tool that reads endoflife.date's API can read it from DOC instead. Give it {{ platform_url }}/api/v1/plugins/eol where it asks for endoflife.date's address, and a DOC token that can read End of life.

curl -H "Authorization: Bearer $DOC_TOKEN" \
  "{{ platform_url }}/api/v1/plugins/eol/api/v1/products/nodejs"

It answers api/v1/products, api/v1/products/full, api/v1/products/<product> and api/v1/products/<product>/releases/<release> (or latest). Each answer carries an ETag, so asking again for what has not changed costs a 304.
