Page editor

A Markdown field in a doc-editor marked data-doc-editor is edited as the formatted page, under a toolbar, and switches to its Markdown for anything the toolbar does not do, such as a new table. It is still the form's field: the formatted page is written back to it as Markdown before the form is sent. Images the Markdown shows from somewhere else are named in data-doc-editor-images, as JSON from the address written to where they are kept, and a page with no Markdown yet starts from the HTML in a template marked data-doc-editor-html.

Page headers

The band at the top of this page, and of every other. The layout draws it from the chrome, so a page is headed by being rendered: it says what the page is called, a sentence on what it is for, and what the page as a whole offers. A plugin's page is headed the same way — the platform lifts the page's first h1 or h2 into the band, so a plugin writes its page as it always has and is headed like the rest of the platform.

A core page fills page_caption, page_lede or page_actions when it has more to put there, and is built with Chrome::bare() when it opens with something of its own instead, as the landing page's hero does.

To the left of the heading is a link to the page itself, which copies the page's address to share with anyone signed in who is allowed to see it. The layout draws it beside every heading, a plugin's too, so no page adds its own.

Content pages

A page written to be read rather than worked in — guidance, a policy, a plugin's own explanation. This page is one: doc-content-page holds it to one measured column, its heading block says what it is and when it changed, and its sections carry more air than a page of controls does.

Code

A file, a request or a config value to read or copy, drawn dark as an editor is. A block says what it holds with data-doc-language, or lets its data-doc-filename say it, and the platform colours it in VS Code’s Dark+ palette, on that theme’s own background: a comment, a string, a number, a setting’s name, a keyword, a name taken for a type and a name taken for a call. Every one of them clears AA against the block. The colour only ever repeats what the word already is, so a block reads the same before the script runs, on paper, and in high contrast, where the hues drop out. 

/// Everything DOC holds for this service, read in one call and kept up to date.
pub async fn start(config: &Config) -> Result<Flags> {
    let flags = Flags::read(&config.flags_url, 30).await?;
    if flags.bool("new-pricing", false) {
        tracing::info!(count = 1, "the new pricing is on");
    }
    Ok(flags)
}
